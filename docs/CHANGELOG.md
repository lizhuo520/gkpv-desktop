# 变更记录

本文件记录 gkpv 的重要变更。版本号遵循[语义化版本](https://semver.org/lang/zh-CN/)。
网页版（1.x）与桌面版（2.x）共用同一个仓库：`1.x` 是零依赖单文件网页，
`2.x` 是把它移植成的 Windows 桌面应用（`gkpv.html` 仍在仓库里，作为功能对照基线保留）。

---

## [2.0.0] — 桌面版首版

把 2707 行的零依赖单文件网页移植为 Electron Windows 桌面应用。**功能等价**：图像解码、
EXIF 解析、RAW 处理、虚滚动、灯箱、排序筛选全部沿用原实现，只做「拆分 + 搬运」，
没有重写算法，也没有引入 Node 文件后端。

### 新增

- **独立应用窗口**：不再需要浏览器标签页，也不需要手动跑本地服务。
- **自定义标准协议 `app://gkpv/…`**：把渲染层放在一个**有名字的 secure context** 里，
  于是 OPFS 缩略图缓存与 File System Access API 都能用（`file://` 是不透明源，两者都不可用
  ——这正是原项目必须配 `serve.py` 起本地服务的原因）。不占端口、不过网络栈。
- **应用菜单**：打开文件夹 / 清空缓存 / 诊断 / 关于。
- **单实例**：重复启动不再开新进程，聚焦已有窗口。
- **主进程只读扫盘**（`desktop/main/scandir.cjs`）：用于测试目录注入、首屏快速预取，
  以及与渲染层解析器**交叉校验**（两套独立实现对同一批素材必须给出相同答案）。
- **测试态注入接口**：仅当主进程以 `GKPV_TEST_MODE=1` 启动时，预加载脚本暴露
  `gkpv.test.setFolder(path)`；生产构建里被静态消除，普通用户碰不到。
- **完整测试体系**：72 个测试素材（含真实样本与真实 HEIC）+ 26 条单元测试 + 42 条真 Electron
  窗口的端到端测试 + 打包产物冒烟。
- **GIF 素材的独立验证**（`tests/unit/gif.test.mjs`）：项目里唯一一份手写编码器产出的素材，
  用**按规范另写一遍的解码器**逐点校验，并与冻结的 Pillow 参照物跨编码器比对
  （`npm run gif-reference` 可逐字节复现参照物）。
- **分发产物**：NSIS 安装包与 portable 免安装版（x64）。

### 变更

- 渲染层从单个 `gkpv.html` 拆成 18 个模块（`desktop/renderer/`），便于测试与后续维护。
  拆分过程中把原本散落的模块级变量收进单一 `state` 对象，并加了 `resetState()`，
  让测试可以一次性复位。
- 仓库根目录成为唯一的依赖根（单一 `package-lock.json`）。

### 修复（由新测试体系抓出的原版遗留缺陷）

- **TIFF/RAW 尺寸解析取错字段**：在 SubIFD 结构上拿到了错误的宽高，导致 RAW 磁贴尺寸异常。
  现在按容器 IFD0 与 SubIFD 的正确层级取尺寸，并有断言钉住。
- **SVG 未标注尺寸时被当成 0×0**：导致布局错乱。矢量图现在交给渲染层兜底测量，
  Node 侧刻意不解析（单测里明确断言这一点，避免以后有人「顺手补上」又踩回去）。
- **GIF 图像描述符误置隔行标志位**：手写编码器的位流是逐行顺序，描述符却写成 `0x40`
  （隔行扫描），Chromium 于是按 8/8/4/2 交错行序重排，实心红块显示成「每隔 4 行一条红带」。
  因为前景像素**总数不变**，只看总数的检查毫无反应；最后靠真 Chromium 抽点取像素才发现。
  现在描述符为 `0x00`，并有断言钉住隔行位与前景行的连续性。
- **应用菜单命令全部静默失效**：菜单下发的是 kebab-case（`open-folder`/`size-md`…），
  渲染层的命令表键名是 camelCase，查表必然落空且不报错。现在有别名表 + 机械兜底 + 未知命令跟踪，
  并有用例从 `menu.cjs` 正则扫出全部 ID 逐个断言。
- **自动化的自检通道把 SVG 当无类型二进制**：`readRemote()`（测试态注入用的读盘通道）
  建 Blob 时没带 MIME，`type === ''` 的 SVG Blob 塞进 `<img>` 后 Chromium 直接
  `onerror`（报「SVG 解码失败」）。界面路径一直正常，因为 `getFileFor()` 传了
  `guessMime(name)`——同一份文件两条路径一个有一个没有。现在 `guessMime` 导出并两处共用。

### 说明（非退化，行为与原版一致）

- **HEIC 不解码**：Chromium 本身不支持 HEIC，本项目固定行为是「占位 + 计入失败」。
- **不做代码签名**：首次运行会出现「未知发布者」提示，这是预期行为。
- **本轮不含**：文件关联双击打开、右键「用 gkpv 打开文件夹」、记住上次打开的文件夹。

## 网页版历史（1.x，移植前的开发过程）

- **v1.2** — RAW 方向转正 + RAW EXIF：认识到内嵌预览**不带**方向标记，改为按容器 IFD0 自己转。
- **v1.1** — 修复一批正确性问题：RAW 灯箱空白、EXIF 竖拍方向、扫描上限、SVG 缩略图、HEIC 占位。
- **（无标签）本机部署文件** — 本地静态服务 `serve.py`、启停脚本、诊断页 `diagnose.html`、中文使用说明。

早于上述标签的开发步骤（内容已固化为 git 标签）：

| 标签 | 内容 |
| --- | --- |
| `upstream` | 导入上游原版 `gkpv.html`（零依赖单文件照片浏览器，来自 `karypis/photo-browser`） |
| `en` | 递归显示子文件夹 + 英文界面 |
| `zh` | 简体中文界面（39 处文案） |
| `opt` | 继续优化（本步未提速） |
| `preraw` | 性能提速：只读文件头取尺寸 + 预测量宽高比 |
| `precount` | 缩略图计数修正：失败也计数 + 计数器文案 |
| `prenef` | 相机 RAW 支持：TIFF 内嵌预览 + NEF SubIFDs |

> 历史备份快照（`gkpv.html.en` / `.zh` / `.opt` / `.original` 等）不逐次入库，
> 内容已固化成上表的 git 标签，需要时 `git show upstream:gkpv.html` 即可取回。
